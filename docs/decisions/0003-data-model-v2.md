# ADR 0003: NovaPay Gold data model v2

## Status
Accepted (supersedes the Stage 2 draft model)

## Context
A review of the draft star schema against current Databricks guidance and Kimball
practice found gaps: facts lacked degenerate IDs, event timestamps and lineage
columns; no PK/FK constraints; identity-column limitations not considered; risk of
double-counting bill payments; joint accounts not modelled; transaction descriptors
(channel, type, status) missing.

## Decision
- Star schema in Gold; grain declared for every fact.
- Facts keep degenerate IDs (transaction_id etc.), event_ts (UTC), lineage
  (_source_file, _batch_id); date_key = Europe/Vilnius local business date.
- Informational PRIMARY KEY / FOREIGN KEY constraints with RELY; integrity still
  enforced by pipeline DQ checks (Databricks does not enforce key constraints).
- Dimension surrogate keys: GENERATED BY DEFAULT AS IDENTITY (START WITH 1) so the
  unknown member (-1) can be inserted explicitly. Dimensions are written by a single
  job (identity columns disable concurrent transactions).
- Junk dimension dim_txn_profile (payment_method, channel, transaction_type, status).
- bridge_account_customer for joint accounts.
- fact_support_case as an accumulating snapshot.
- Spend metrics only from fact_transaction; fact_bill_payment for bill behaviour only.
- SCD2 built manually with MERGE (learning); Lakeflow AUTO CDC noted as alternative.

## Consequences
+ Reconcilable, traceable facts; optimizer-friendly constraints; realistic banking model.
- More tables and a bridge join for account-level analysis.
- Key constraints are informational only, so DQ checks remain mandatory.
