# NovaPay Gold data model (v2)

Conventions: `_sk` = surrogate key (BIGINT, GENERATED BY DEFAULT AS IDENTITY),
`_id` = business key, `_dk` = durable key, `-1` = unknown member, money = DECIMAL,
`date_key` = Europe/Vilnius local date (yyyymmdd), timestamps stored in UTC.

## Facts
| Table | Type | Grain | Columns |
|---|---|---|---|
| fact_transaction | Transaction | one transaction | transaction_id (PK), event_ts, date_key, customer_sk, account_sk, merchant_sk, txn_profile_sk, original_transaction_id, amount, currency, fx_rate, amount_eur, _source_file, _batch_id |
| fact_bill_payment | Transaction | one bill payment | transaction_id (PK), date_key, due_date_key, customer_sk, biller_sk, amount, days_late |
| fact_holding_snapshot | Periodic snapshot | customer x product x day | date_key, customer_sk, product_sk (PK on all three), units, market_value |
| fact_kyc_check | Transaction | one KYC check | kyc_check_id (PK), date_key, customer_sk, check_type, result |
| fact_support_case | Accumulating snapshot | one case | case_id (PK), customer_sk, opened_date_key, first_response_date_key, resolved_date_key, channel, reason, resolution_hours |

## Dimensions
| Table | SCD | Key columns | Attributes |
|---|---|---|---|
| dim_customer | 2 | customer_sk, customer_id, customer_dk | segment, city, country, kyc_status, risk_rating, valid_from, valid_to, is_current, row_hash |
| dim_account | 2 | account_sk, account_id | account_type, status, open_date, valid_from, valid_to, is_current |
| bridge_account_customer | 2 | account_sk, customer_sk | role (primary/joint), valid_from, valid_to |
| dim_merchant | 2 | merchant_sk, merchant_id | merchant_name, mcc, category, country |
| dim_txn_profile | 1 (junk) | txn_profile_sk | payment_method, channel, transaction_type, status |
| dim_biller | 1 | biller_sk, biller_id | biller_name, bill_type |
| dim_invest_product | 2 | product_sk, isin | product_name, asset_class, risk_level |
| dim_date | 0 | date_key | date, month, quarter, year, is_weekend |

## Rules
- Spend and transaction KPIs come only from fact_transaction.
- fact_bill_payment is used only for bill behaviour (never summed with fact_transaction).
- Refunds/reversals are new rows linked by original_transaction_id; originals are never updated.
- PK/FK constraints are declared with RELY and validated by DQ checks every run.
